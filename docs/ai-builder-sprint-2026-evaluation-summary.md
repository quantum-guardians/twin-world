# AI BUILDER SPRINT 2026 평가 핵심 요약

> 원본: `AI_Builder_Sprint_OT.pdf`  
> 정리 범위: 일정, 참가 조건, 적격성, 예선·본선 평가, 제출물, 가점, 모두싸인 특별상  
> 주제: **AI를 통해 인간다움을 더욱 잘 드러낼 수 있는 서비스 개발**

## 한눈에 보는 최우선 사항

1. **적격성 심사를 먼저 통과해야 한다.** 한 항목이라도 미충족하면 점수 심사 없이 제외된다.
2. **예선 제출 마감은 2026년 8월 3일 18:00이다.**
3. 예선은 **창의성·AI 활용도·완성도·실용성 각 20점**, 총 80점이다.
4. AI는 단순히 붙이는 기능이 아니라 **문제 해결과 개발 과정 전반에 필수적으로 통합**되어야 한다.
5. 실제 작동하는 핵심 기능, 자연스러운 사용자 흐름, 코드 품질과 오류 처리가 모두 평가된다.
6. README나 코드 주석에 심사 지시를 넣는 **프롬프트 인젝션은 적발 즉시 실격**이다.
7. 본선은 예선 80점을 다시 평가하고 **발표력 20점**을 추가한다. 별도 가점은 최대 10점이다.

### 특히 주의할 점

- 원문 페이지마다 배포 링크와 데모 영상의 표현이 조금 다르다. 실격 위험을 최소화하려면 **작동하는 배포 링크와 데모 영상 모두** 준비하는 것이 안전하다.
- 저장소의 README, 실행 방법, 주요 코드, 커밋 이력, AI 지침 파일을 심사자가 바로 찾을 수 있게 정리한다.
- README·코드 주석·AI 지침 파일 어디에도 심사자나 평가 에이전트에게 특정 판정·점수를 요구하는 문구를 넣지 않는다.

|  | 결과물 품질 기여도 | 5 |

|  | 서비스 이용 흐름 | 5 |

### 배점에서 읽어야 할 핵심

- 네 개 대분류가 모두 20점이므로 아이디어만 새롭거나 AI만 화려해서는 높은 점수를 받기 어렵다.
- 단일 세부 항목에서 가장 큰 배점은 모두 10점이다. 다음 여섯 항목을 우선 확보해야 한다.
  - 문제 정의·아이디어 독창성
  - 핵심 기능의 참신성
  - 개발 과정 전반의 AI 통합
  - 핵심 기능 구현 및 정상 작동
  - 문제의 구체성·타당성
  - 실제 활용 가능성·기대 효과
- AI 활용은 사용 모델명만 나열하는 것으로 부족하다. **어디에, 왜, 어떻게 사용했고 결과 품질이 얼마나 좋아졌는지** 증명해야 한다.

## 평가 운영 방식과 대응

- AI 에이전트가 적격성 자동 판정과 점수 초안을 만들고, 심사위원 3인이 리포트를 참고해 최종 채점한다.
- 팀별 평가를 독립적으로 3회 실행해 평균을 산출하며, 편차가 큰 팀은 심사위원이 정밀 재검토한다.
- 심사위원 구성: Upstage 엠버서더, APPTIVE 1인, Untoc 1인

따라서 제출물은 사람뿐 아니라 평가 에이전트도 핵심 근거를 쉽게 찾을 수 있도록 다음처럼 명확하게 구성하는 것이 유리하다.

- README 첫 부분에 문제, 대상 사용자, 핵심 기능, AI가 필요한 이유, 실행·데모 방법을 요약
- 기능별로 입력 → AI 처리 → 출력 → 검증 방법을 구분
- 실행 절차와 환경 변수, 테스트 계정, 오류 상황을 재현 가능하게 설명
- AI 적용 전후 또는 기준선과 비교한 테스트·검증 결과 제시
- 커밋 이력과 AI 지침·설정 파일을 일관된 구조로 유지

## 본선 평가: 100점 + 가점 최대 10점

- 예선의 네 항목 80점을 동일하게 재평가
  - 창의성 20
  - AI 활용도 20
  - 완성도 20
  - 실용성 20
- 발표력 20점 추가
  - 발표 구성·논리성 10
  - 시연·Q&A 대응 10
- 발표 시간: 발표 7분 + Q&A 5분
- 가점
  - Upstage API 활용: +5
  - 지역사회 기여도: +5

### 본선에서 강조할 발표 흐름

1. **사람에게 실제로 필요한 문제**를 구체적인 사용자 상황으로 제시한다.
2. 기존 방식의 한계와 **AI가 반드시 필요한 이유**를 연결한다.
3. 가장 중요한 사용자 흐름을 실제 데모로 보여준다.
4. 테스트·비교 결과로 정확성, 안정성, 품질 기여도를 증명한다.
5. 실제 활용 가능성과 기대 효과를 수치나 구체적 사례로 마무리한다.
6. 오류·한계·안전장치에 대한 예상 질문과 답변을 준비한다.

## Upstage API 가점

Upstage API를 활용하면 본선 평가에서 +5점을 받을 수 있으며, 타사 모델과 병행할 수 있다.

- Solar LLM: 에이전트 추론·대화 처리
- Document Parse: PDF·이미지의 텍스트와 구조 추출
- Information Extract: 문서의 핵심 정보를 구조화해 추출

가점을 위해 억지로 추가하기보다는 핵심 문제 해결 흐름에 실제로 통합하고, 코드 위치·프롬프트·테스트 결과를 증빙해야 전체 AI 활용도 평가에도 도움이 된다.

## 모두싸인 특별상

전자서명·CLM을 계약 경험에 실제 구현한 팀을 대상으로 하며, FAQ에는 **상금 + 인턴십**이 명시되어 있다.

### 제시 과제

1. **부산 관광 상생 계약 비서**: 관광 계약·약관의 불리한 조항을 AI가 점검하고 전자서명으로 증빙
2. **마음을 남기는 서명**: 기부·봉사·유산기부 약정을 AI 대화로 정리하고 전자서명으로 체결·관리

### 특별상 평가 기준: 100점 + 가점 최대 10점

| 평가 항목 | 세부 항목 | 배점 |
|---|---|---:|
| CLM·API 활용도 | 전자서명 플로우 실제 구현: 요청 → 서명 → 완료 | 15 |
|  | 계약 생애주기 커버리지·다단계 연계 | 12 |
|  | 상태 동기화·예외 처리 등 연동의 견고성 | 8 |
| 실용성 | 문제 정의의 구체성·타당성 | 12 |
|  | 실제 활용·확산 가능성 | 13 |
| 인간다움 | 계약·서명 경험을 더 사람답게 만든 정도 | 15 |
| AI 활용도 | Upstage 등 AI를 계약 파이프라인에 실질 통합 | 10 |
|  | AI의 정확성·안정성 등 결과 품질 기여 | 5 |
| 완성도 | 데모 정상 동작·UI/UX·문서화 | 10 |

특별상 가점은 부산 지역·관광 결합 +5, 사회적 임팩트·약자 보호 +5이다. 특별상에서는 **전자서명 플로우를 실제로 끝까지 구현하는 것**과 **계약 상태 동기화·예외 처리**가 가장 중요한 차별점이다.
