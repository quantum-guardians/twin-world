# 2026-08-02 - Twin World MVP 기획

- Date: 2026-08-02
- GitHub Issue: None
- Status: Draft

## Goal

행사 안전관리자와 지자체 담당자가 행사 전에 거리 그래프, 예상 인원, 출입구와 목적지를 설정하고 군중 이동을 3D로 시뮬레이션하여 일방통행 동선의 위험도를 검토할 수 있는 웹 MVP를 만든다.

핵심 가치는 다음과 같다.

> 동일한 행사 조건에서 기존 동선과 최적화된 일방통행 동선을 비교하여 밀집 위험, 병목, 예상 대피시간의 변화를 근거로 의사결정을 돕는다.

### 성공 조건

- 관리자가 거리 그래프를 만들거나 준비된 실제 장소 그래프를 불러올 수 있다.
- 관리자가 노드·간선 위치, 거리 폭, 출입구, 목적지와 예상 인원수를 설정할 수 있다.
- 입력 그래프에서 간단한 3D 거리·건물 모델이 생성된다.
- 각 에이전트가 개별 목적지를 가지고 경로를 따라 실제로 이동한다.
- Social Force Model을 이용해 에이전트 간·벽 간 충돌과 압력을 계산한다.
- 기준 동선과 MR2S가 제안한 일방통행 동선을 같은 조건으로 실행할 수 있다.
- 바닥 밀집도 히트맵, 위험구역, 병목, 대피 완료시간을 확인할 수 있다.
- AI가 자연어 시나리오를 구조화하고 시뮬레이션 수치를 근거로 위험 원인, 개선안, 분석 보고서를 생성한다.
- 부산의 실제 축제·공연장 거리 사례 하나를 데모해 지역사회 기여도를 설명한다.

## Non-goals

- 실시간 CCTV 군중 추적이나 행사 중 실시간 관제
- 실제 인명 피해를 정확히 예측하거나 법적·행정적 안전 판정을 대신하는 기능
- 도시 전체, 다층 건물, 지하 공간을 동시에 처리하는 대규모 디지털 트윈
- 실제 GIS·3D 건물 데이터를 완전 자동 변환하는 범용 파이프라인
- 연령, 장애, 짐, 집단 행동 등 모든 보행자 특성을 정밀하게 재현
- 최적 동선을 자동 확정하는 기능: 시스템은 후보와 근거를 제시하고 최종 결정은 관리자가 수행
- 시각적 완성도가 높은 도시 제작 도구: MVP에서는 분석 가능한 단순 거리·건물 형상을 우선

## Context / Constraints

- 대표 공간: 부산 지역의 축제·공연장 주변 거리

### Step 0 Recon 결과 (2026-08-02)

같은 `Develope` 폴더 아래 형제 디렉터리에서 문서가 가리키는 실제 소스를 모두 찾음. 이 저장소(`twin-world`)에는 아직 앱 코드가 전혀 없으므로 아래 소스는 **복사가 아니라 포팅/재구현 참고용**으로 사용한다 (2D top-down → 3D 렌더링으로 표현 계층이 달라지므로 그대로 복붙 불가).

- `../simulation_react` — React 19 + TypeScript + Vite. **2D top-down Social Force 시뮬레이션이 이미 동작 중**.
  - `src/simulation/{graph,corridors,density,pressure,socialForce,agents,presets,draw}.ts` — 그래프→복도 변환, Dijkstra 경로탐색, SFM 물리, 압력사망 모델, 코리도 점유율(밀집도) 계산까지 전부 구현되어 있고 각 모듈에 대응하는 `*.test.ts`도 있음. **핵심 물리·경로·밀집도 로직의 포팅 베이스**로 사용.
  - `src/api/client.ts` — MR2S 백엔드 V1 API 클라이언트(408/타임아웃 처리 포함).
  - `vite.config.ts`의 `server.proxy['/mr2s-api']` — **배포된 MR2S 백엔드가 로컬호스트 CORS를 허용하지 않아서 dev 프록시로 우회**하는 패턴. `.env.example`에 `VITE_PROXY_TARGET` 확인됨.
  - **`.env.example`에 실제 배포 주소가 적혀 있음: `https://quantum.yunseong.dev`.** 로컬에서 mr2s-backend를 새로 띄울 필요 없이 이 배포 서버를 바로 호출 가능(Open Question 5 해소).
  - 3D 렌더링 라이브러리는 없음(캔버스 2D뿐) — twin-world의 3D 요구사항은 새로 구성해야 함.
- `../mr2s-frontend` — React 19 + Vite + `@xyflow/react`(React Flow) + `@dagrejs/dagre` 기반 **그래프 편집/시각화 UI**가 이미 동작 중(`GraphInput`, `GraphVisualization`, `CircleNode`, `SimulationPage`, `BenchmarkPanel`, `ResultPanel`). `vercel.json` rewrite로 프로덕션에서도 같은 프록시 패턴 사용. 그래프 편집 UX(노드/간선 CRUD, 레이아웃)의 참고 구현으로 활용.
- `../mr2s-backend` — FastAPI, `docs/BACKEND_REFERENCE.md`와 100% 일치하는 실제 구현. 이미 `https://quantum.yunseong.dev`에 배포되어 있어 twin-world는 **API 소비자로만** 동작하면 됨. 저장소 자체를 twin-world로 가져올 필요 없음.
- `../mr2s-module` — mr2s-backend가 의존하는 Python 솔버 라이브러리(`docs/API.md`와 일치). 백엔드 내부 의존성이며 프론트에서 직접 다룰 일 없음.
- `../mr2s-analysis` — 그래프 벤치마크/스코어 계산용 Python CLI. 부산 실제 장소 데이터는 없음(합성 그래프 생성기뿐). 재사용 대상 아님.
- `../QUBO_simulation` — Unity(C#) 프로젝트. 기술 스택이 완전히 다른 별도 실험이며 React 웹 MVP에 재사용 불가.

**결론**: MR2S 프론트·백엔드·시뮬레이션 소스는 모두 존재하며 라이선스 문제 없음(동일 사용자 소유 저장소). 새로 만들어야 하는 것은 (1) 3D 렌더링 계층, (2) 부산 프리셋 그래프 편집 UI(React Flow 스타일 참고해 3D 씬과 연동), (3) 밀집도 히트맵의 3D 시각화, (4) 기준안/최적화안 비교 화면, (5) Upstage 연동 3종 기능 전체. 물리·경로·MR2S 클라이언트·프록시 패턴은 포팅 대상.

**사용자 확인 사항**:
- Upstage API 키는 지금 사용 가능 — `.env.local`(커밋 금지)로 전달받아 서버리스 프록시에서만 사용.
- 부산 실제 장소의 좌표/지도 자료는 없음 — 실제 GIS 데이터 대신 부산의 대표 축제 거리 형태를 본뜬 **가상 프리셋**(노드/간선 상대 좌표)으로 진행하고, 보고서·README에 "실측 좌표 아님" 한계를 명시.

### 중요한 기술 제약

- MR2S는 무방향 그래프의 간선 방향을 최적화하지만 직접 군중 밀집도를 최소화하는 솔버는 아니다.
- MR2S 결과는 일방통행 후보로 사용하고, 실제 안전성은 동일 조건의 Social Force 시뮬레이션 지표로 다시 검증해야 한다.
- MR2S API는 정점 좌표를 받지 않는다. 프론트엔드가 노드 좌표, 거리 폭, 건물 형상과 정점 ID 매핑을 별도로 보존해야 한다.
- 그래프만으로 실제 건물을 복원할 수 없다. MVP의 3D 모델은 간선을 거리 복도로 만들고 주변을 단순 건물 블록으로 채우는 절차적 모델로 제한한다.
- 압력·사망 임계값은 현실 검증 전까지 상대 비교 지표로만 사용한다. 화면과 보고서에는 실제 피해 예측값이 아니라 `고압력 위험 노출`로 표현한다.
- Upstage API 키는 브라우저에 노출하지 않고 백엔드 또는 서버리스 프록시에서 사용한다.

## Product Definition

### 핵심 사용 시나리오

1. 관리자가 부산의 특정 축제 거리 프리셋을 선택하거나 그래프를 직접 작성한다.
2. 노드와 간선 위치를 수정하고 거리 폭, 출입구, 목적지 유형을 지정한다.
3. 자연어로 행사 상황을 입력한다.
   - 예: `18시부터 3,000명이 북쪽 입구로 유입되고 공연 종료 후 남쪽 출구로 이동한다.`
4. AI가 자연어를 인원수, 유입 지점, 목적지, 시간 조건으로 구조화하고 사용자가 이를 확인·수정한다.
5. 기준 동선으로 에이전트 시뮬레이션을 실행한다.
6. MR2S가 생성한 일방통행 후보를 적용해 같은 조건으로 다시 실행한다.
7. 관리자가 두 결과의 히트맵, 병목, 위험 노출, 대피시간을 비교한다.
8. AI가 수치와 위치 정보를 근거로 원인, 개선안, 최종 분석 보고서를 작성한다.

### MVP 화면

| 화면 | 핵심 기능 |
|---|---|
| 프로젝트/장소 선택 | 부산 실제 장소 프리셋 1개 선택, 새 그래프 시작 |
| 그래프 편집 | 노드·간선 추가/이동/삭제, 폭·출입구·목적지 설정 |
| 시나리오 설정 | 자연어 입력, 인원수와 목적지 분포 확인·수정 |
| 3D 시뮬레이션 | 에이전트 이동, 재생·정지·배속, 바닥 히트맵, 위험 표시 |
| 결과 비교 | 기준안과 일방통행안의 핵심 지표 및 병목 위치 비교 |
| AI 보고서 | 위험 원인, 개선 제안, 한계, 요약 보고서 확인·내보내기 |

## MVP Scope

### P0 - 제출에 반드시 필요한 기능

1. 그래프 편집
   - 노드와 간선 생성·이동·삭제
   - 정점 ID와 좌표 유지
   - 간선 길이와 거리 폭 설정
   - 출입구·목적지 노드 지정
   - 방향 적용 전·후 그래프 표시
2. 절차적 3D 공간 생성
   - 간선을 폭이 있는 거리 바닥으로 변환
   - 거리 밖 영역에 단순 건물 블록 생성
   - 시뮬레이션 좌표와 3D 좌표 일치
3. 에이전트 시뮬레이션
   - 입력 인원수만큼 거리 위에 분산 생성
   - 각 에이전트에 도달 가능한 목적지 배정
   - Dijkstra 경로 탐색
   - Social Force Model 기반 이동·충돌·벽 반발
   - 고정 타임스텝, 재생·정지·배속
4. 위험 분석
   - 바닥 밀집도 히트맵
   - 고밀도 지속 구역 표시
   - 병목 간선·노드 표시
   - 95% 도착시간 또는 제한시간 내 도착률
   - 고압력 위험 노출 에이전트 수·시간
5. 일방통행 최적화
   - MR2S V1 API 호출
   - 반환된 `_from -> to` 방향을 프론트 그래프에 적용
   - 400·408·500 오류와 `-1` 연결 불가 결과 처리
   - 기준안과 최적화안에 동일한 시드·인원·목적지 분포 적용
6. AI 기능
   - 자연어 시나리오를 검증 가능한 구조 데이터로 변환
   - 시뮬레이션 결과 JSON을 근거로 위험 원인 분석
   - 구체적인 배치·동선 개선안 생성
   - 결과·근거·한계를 포함한 분석 보고서 생성
7. 제출 가능한 데모
   - 부산 실제 축제 거리 사례 1개
   - 배포 URL, 테스트 시나리오, 데모 영상
   - README 실행 방법과 AI 활용 증빙

- 여러 시나리오 저장·불러오기

- GIS·OpenStreetMap 자동 도로망 추출
- 실제 건물 높이·외관 재현

| FR-03 | 3D 생성 | 편집 결과와 일치하는 거리 바닥·벽·단순 건물이 3D로 생성됨 |
| FR-04 | 에이전트 생성 | 설정한 수만큼 유효한 거리 위치에 중복을 최소화해 생성됨 |
| FR-05 | 목적지 이동 | 모든 활성 에이전트가 개별 목적지와 유효한 경로를 가짐 |
| FR-06 | 물리 이동 | 에이전트가 벽을 통과하지 않고 서로 반발하며 경로를 따라 이동함 |
| FR-07 | 위험 시각화 | 밀집도가 높아질수록 바닥 색이 변하고 위험 위치가 강조됨 |
| FR-08 | 결과 지표 | 도착률·대피시간·최대 밀집·병목·위험 노출을 확인할 수 있음 |
| FR-09 | 공정 비교 | 기준안과 최적화안이 같은 랜덤 시드와 조건으로 실행됨 |
| FR-10 | 자연어 입력 | AI 출력 스키마 오류를 검증하고 사용자 확인 후에만 시뮬레이션에 반영함 |
| FR-11 | AI 분석 | AI 보고서의 각 주요 판단에 사용한 시뮬레이션 지표·위치가 포함됨 |
| FR-12 | 실패 처리 | MR2S 시간 초과, 연결 불가, AI 실패 시 재시도·수동 입력 경로를 제공함 |

## Data Model

```text
Venue
  id, name, region, mapReference, scaleMetersPerUnit
  nodes[], edges[], obstacles[]

Node
  id, x, y, kind(normal | entrance | exit | destination)

Edge
  id, fromNodeId, toNodeId, length, width, direction
  direction = bidirectional | forward | reverse

Scenario
  id, population, spawnRules[], destinationRules[]
  durationSeconds, randomSeed, agentProfile

SimulationRun
  scenarioId, graphVersion, mode(baseline | optimized)
  startedAt, status, metrics, heatmapFrames[], bottlenecks[]

AnalysisReport
  comparedRunIds[], summary, causes[], recommendations[]
  evidence[], limitations[]
```

MR2S 요청에는 `Edge.length` 또는 합의된 이동 비용을 정수 `weight`로 변환해 전달한다. 좌표와 폭 등 시각·물리 정보는 프론트 시나리오에 남긴다.

## Simulation and Metrics

### 이동 모델

- 경로 계층: 방향 그래프 기반 Dijkstra
- 물리 계층: Social Force Model
- 벽과 에이전트 접촉 반발, 개인별 속도 편차, 경로 이탈 제한 적용
- 도착한 에이전트는 MVP 비교의 명확성을 위해 해당 실행에서 제거하거나 완료 상태로 고정한다. 기존 레퍼런스의 자동 재목적지 배정은 연속 흐름 모드로 분리한다.
- 두 비교 실행은 같은 랜덤 시드와 스폰·목적지 할당을 사용한다.

### 핵심 지표

| 지표 | 정의 |
|---|---|
| 도착률 | 제한시간 안에 목적지에 도착한 에이전트 비율 |
| 예상 대피시간 | 전체 또는 95% 에이전트가 목적지에 도착한 시뮬레이션 시간 |
| 최대 밀집도 | 공간 셀별 관측된 최대 에이전트 밀도 |
| 고밀도 노출 | 기준 밀도 이상인 셀에서 에이전트가 보낸 누적 시간 |
| 병목 | 낮은 이동 속도와 높은 밀도가 일정 시간 함께 유지된 노드·간선 |
| 고압력 위험 | 압력 기준 이상 상태에 노출된 에이전트 수와 지속시간 |

실제 사람/㎡ 단위를 표시하려면 지도 축척과 거리 폭을 미터 단위로 보정해야 한다. 축척이 확정되지 않은 경우 상대 위험도와 두 대안 간 변화율만 표시한다.

## AI Design

### 역할 1 - 자연어 시나리오 구조화

- 입력: 행사 설명, 예상 인원, 유입 시간, 출입구·목적지 설명
- 출력: JSON 스키마에 맞는 `Scenario` 초안
- 안전장치: 허용된 노드 ID와 수치 범위를 검증하고 사용자 확인 후 적용

### 역할 2 - 위험 원인 분석

- 입력: 그래프 요약, 병목 위치, 밀집·압력·대피 지표
- 출력: 원인, 근거 지표, 영향 구역
- 원칙: 시뮬레이션에 없는 사실이나 실제 사상자 수를 생성하지 않음

### 역할 3 - 개선안 추천

- 입력: 기준안과 최적화안 비교, 수정 가능한 출입구·방향·폭 조건
- 출력: 간선 방향 변경, 출입구 분산, 유입량 조절 등 실행 가능한 후보
- 원칙: 자동 적용하지 않고 관리자 승인 후 새 대안으로 재실행

### 역할 4 - 분석 보고서

- 문제와 조건
- 기준안·최적화안 비교표
- 주요 위험구역과 원인
- 권고안과 예상 효과
- 시뮬레이션 가정·한계

Upstage Solar LLM을 우선 사용해 가점을 확보한다. 실제 지도 이미지나 문서에서 장소 정보를 추출해야 할 경우에만 Document Parse 또는 Information Extract를 추가한다.

## Demo Story

부산의 대표 축제 거리 한 곳을 프리셋으로 준비한다.

1. 행사 종료 시 특정 출구로 군중이 집중되는 자연어 상황을 입력한다.
2. AI가 인원·유입 지점·목적지 분포를 구조화한다.
3. 기존 양방향 또는 수동 동선을 시뮬레이션해 병목과 고밀도 구역을 보여준다.
4. MR2S가 일방통행 방향 후보를 생성한다.
5. 같은 조건으로 다시 시뮬레이션한다.
6. 대피시간, 최대 밀집도, 위험 노출 변화를 비교한다.
7. AI가 개선 이유와 추가 권고안을 보고서로 작성한다.

발표의 핵심 메시지는 `AI가 동선을 임의로 결정했다`가 아니라 `최적화가 후보를 만들고 물리 시뮬레이션과 근거 기반 AI 분석이 그 후보를 검증했다`로 잡는다.

## Validation

- **Commands to run:** 저장소에 앱 구성과 패키지 스크립트가 아직 없어 현재는 확정할 수 없다. 구현 시 `package.json`에 정의된 lint, type-check, test, build 명령만 사용한다.
- **Expected output:**
  - 그래프 편집부터 AI 보고서까지 대표 시나리오가 중단 없이 완료됨
  - 같은 시드의 재실행에서 동일한 초기 에이전트와 목적지 배정이 재현됨
  - 최적화 방향이 MR2S 응답과 일치함
  - 히트맵·병목·대피 지표가 시뮬레이션 상태와 일치함
  - API 키가 클라이언트 번들·네트워크 응답·저장소에 노출되지 않음
  - 프로덕션 빌드 성공 및 배포 URL에서 데모 프리셋 실행 가능

## Risks & Rollback

- **Risks:**
  - 외부 레퍼런스 소스가 없어 문서만으로 시뮬레이션을 다시 구현해야 할 수 있음
  - 3D 렌더링과 다수 에이전트 물리 계산을 한 브라우저에서 수행하면 성능이 부족할 수 있음
  - MR2S의 APSP·흐름 최적화 결과가 실제 밀집 위험을 항상 개선하지 않을 수 있음
  - 지도 축척과 모델 계수가 없으면 절대 밀집도·대피시간의 현실성이 부족함
  - AI가 시뮬레이션 근거를 벗어난 개선안이나 과도한 안전 주장을 생성할 수 있음
  - 외부 MR2S·Upstage API 장애 또는 CORS 문제로 발표 데모가 중단될 수 있음
- **Rollback steps:**
  - 3D 성능이 부족하면 건물·그림자·후처리를 제거하고 단순 지오메트리와 낮은 에이전트 수로 전환
  - MR2S 호출 실패 시 사전에 검증한 방향 결과를 로컬 프리셋에서 불러오되 데모에서 폴백임을 표시
  - AI 호출 실패 시 구조화된 수동 입력과 템플릿 기반 결과 요약으로 핵심 시뮬레이션 흐름 유지
  - 실제 단위 보정이 불가능하면 절대 수치 대신 기준안 대비 변화율과 상대 위험도로 표현
  - 구현이 지연되면 새 지도 생성·PDF 내보내기를 제외하고 부산 프리셋 1개와 비교 데모에 집중
